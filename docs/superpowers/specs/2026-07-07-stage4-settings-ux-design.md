Key facts driving the design:
- **Brightness path** (`SettingsHelper.setBrightness` → `notifySettingsChanged` broadcast → service `mSettingsChangedReceiver` → `pushBrightness(int)` → `nativeSetBrightness(value/100f)`). The **500 ms delayed push exists in both** consumers: `OpenTTDWallpaperService.onSurfaceCreated` (`postDelayed(() -> pushBrightness(), 500)`, `OpenTTDWallpaperService.java:265-266`) and `GameActivity.pushBrightnessDelayed()` (`GameActivity.java:58-66`). The service `pushBrightness` is guarded by `sLibrariesLoaded && sSDLInitialized` (`OpenTTDWallpaperService.java:158`); the GameActivity path is unguarded and relies on the JNI null-check `if (GLESBackend::Get() != nullptr)` (`sdl2_gles_v.cpp:158,183`). Brightness is also re-pushed on `onVisibilityChanged(true)` (`OpenTTDWallpaperService.java:330`).
- **Interval / zoom** are broadcast as intent extras by `SettingsHelper.notifySettingsChanged` (`SettingsHelper.java:53-59`) but the service receiver (`OpenTTDWallpaperService.java:135-146`) reads them into locals, `Log.i`s them, and consumes only brightness.
- **Auto map rotation IS LIVE on `lwp2` today — corrected (Stage-2 landed).** `src/video/gles_poi.cpp` is the real scanner (600 lines). `PrepareBackground()` (`gles_poi.cpp:524-557`): rescans POIs if the map changed (shows POI[0], returns), otherwise sets `_poi_manual_browse = false` (:541), advances `_gles_poi_idx = (idx+1) % n` (:545), and **on wrap→0 calls `RequestNextTitleMap()`** (:549-553) — gated by `!_poi_manual_browse && _switch_mode == SwitchMode::None && CanRotateTitleMap()`. This runs on `onVisibilityChanged(false)` (→ `nativePrepareBackground()`, `OpenTTDWallpaperService.java:339`). **So each home-screen hide advances one POI, and a full POI cycle (~20 hides) rotates to the next title map.** `NavigatePOI(int)` sets `_poi_manual_browse = true` (:518) so manual browsing does NOT auto-rotate. Manual broadcast rotation (`SWITCH_MAP`/`NEXT_MAP`/`PREV_MAP` → `nativeSwitchMap`/`nativeRotateMap`) still exists in parallel. There is still no *time-based* rotation — that gap is what the interval feature (§2) fills, and it must coexist with this live POI-wrap rotate (double-fire risk, now real — see Known risk + §2).
- **`nativeSwitchMap` vs `nativeRotateMap` threading (real, load-bearing for §4):** `nativeSwitchMap` calls `RotateTitleMap(1)` **directly on the JNI binder thread** (`sdl2_gles_v.cpp:108-112`) — a **known latent race** flagged in Stage 1 (fix = route via an atomic in `ProcessOverlayActions` if it misbehaves). `nativeRotateMap` instead sets the `_gles_rotate_map` atomic (:120-124, `_gles_rotate_map` declared :58) drained in `ProcessOverlayActions` (:475-476) under `game_state_mutex` (:467). The mutex-guarded drain is the **device-validated** pattern; the direct call is the risky precedent — §4 deliberately follows the drain, not the direct call.
- **Title file list is a static cache:** `wallpaper.cpp` holds `static std::vector<std::pair<std::string,Subdirectory>> _title_files` (:33) + `static size_t _title_file_idx` (:34); `BuildTitleFileList()` clears+rescans (bundled `opntitle.dat` + `title/*.sav` from `OPENTTD_DATA_PATH`/search paths, :40-77); `LoadNextTitleMap()` rebuilds **only if `_title_files` is empty** (:104); `RotateTitleMap` just modulo-advances the index, no rebuild (:89-95); `RequestNextTitleMap = RotateTitleMap(1)` (:84-87). So an import/delete does not reach a running wallpaper until the list is rebuilt.
- **`copyAssetsStatic` overwrites unconditionally:** `MainActivity.copyAssetDir` re-copies bundled `title/*.sav` from APK assets to `filesDir/title/` on every launch — the file branch writes with NO dest-existence check (only parent-dir mkdirs at :114-116, dir mkdirs at :129-131; copy at :117-124). Deleting an **imported** map persists; deleting a **bundled** map reappears on next process launch.
- **Process boundary:** `WallpaperSettingsActivity` + `MapsActivity` run in the app's default process; `OpenTTDWallpaperService` in `:wallpaper`; `GameActivity` in `:game` (per `AndroidManifest.xml`). Native is loaded only in `:wallpaper`/`:game`, so settings/maps UIs **cannot call native directly** — they cross the boundary via `SharedPreferences` (persisted, shared file) + broadcasts (live signal). `filesDir/title/` is shared across all processes in the app sandbox.

## Scope

### 1. Brightness — harden the existing end-to-end path

- Keep the wired path as-is. Fixes:
  - **SeekBar range wart:** `seekbar_brightness android:max="99"` but `DEFAULT_BRIGHTNESS=100` and `pushBrightness` divides by 100 → the slider caps at 0.99 brightness and clamps the default down to 99 on display. Set `max="100"` (or scale by the seekbar max) so 100% → 1.0 and the default renders correctly.
  - **Single-shot delayed push is not a real retry:** `GameActivity.pushBrightnessDelayed`'s comment says "Retry until it accepts" but it fires **once** at 500 ms; if `GLESBackend` is still null, brightness silently stays at default until the next visibility/settings change. Replace with a bounded retry (e.g. re-post every 250 ms up to ~2 s until `GLESBackend::Get()` is non-null — requires either a native "is-ready" query or an idempotent re-push). Apply the same bounded retry in the service `onSurfaceCreated` push. Keep it minimal; brightness re-push on `onVisibilityChanged(true)` already covers the steady state.
- No new native. No CMake change.

### 2. Map-rotation interval — add UI + a cadence consumer

- **UI (`WallpaperSettingsActivity` + `activity_wallpaper_settings.xml`):** add a labelled selector (Spinner or click-to-dialog row, styled like the existing `row_title_maps`) using `map_interval_title` + the five `interval_*` strings, bound to `SettingsHelper.get/setMapUpdateInterval`. Index semantics fixed by the existing strings: `0 = every home-screen switch`, `1 = 10 min`, `2 = 30 min` (current default), `3 = 2 h`, `4 = 24 h`. Refresh selection in `refreshAll()`.
- **Consumer (in `:wallpaper`):** the `SETTINGS_CHANGED` receiver must (re)configure rotation cadence from the `interval` extra instead of just logging it.
  - `index 0` ("every home-screen switch") — **reuse the existing on-hide `nativePrepareBackground()` (decided f/Q4.1).** No new rotate call, no Handler, no suppression flag: the existing `onVisibilityChanged(false)` → `nativePrepareBackground()` path IS the cadence. `PrepareBackground()` advances one POI per hide and rotates to the next title map on POI-wrap (`gles_poi.cpp:543-554`). So "every home-screen switch" = advance the POI camera each switch; the title map rotates once the POI cycle wraps (~20 switches). **Interval-0 leaves `_gles_interval_active` false** — the POI-wrap rotate is the intended index-0 authority. Semantic note: index-0 is POI-advance-per-switch, not a full title-map rotation on every switch.
  - `index 1–4`: a periodic timer at 10 m / 30 m / 2 h / 24 h that triggers a map rotation. **Timer location (decided b): a Java `Handler` in the service**, armed on `onVisibilityChanged(true)` / `SETTINGS_CHANGED`, cancelled on `onVisibilityChanged(false)` (don't rotate while hidden; re-arm on next resume). No new native for the timer; process death re-arms on next resume. The timer fires `nativeRotateMap(1)` (atomic-drain). **Double-fire guard (decided b′/i/j): while an index 1–4 is active, set `nativeSetIntervalActive(true)` so the on-hide POI-wrap `RequestNextTitleMap()` is suppressed** — the timer becomes the sole title-map-rotation authority. `nativePrepareBackground()` still runs on hide (POI *camera* advance continues, keeping the view varied); only its title-map rotation is gated off.
- **Cadence authority (decided b′) — a LIVE Stage-4 concern, mechanism now pinned.** The interval index owns cadence. Gate the POI-wrap rotation by wrapping **`RequestNextTitleMap()` itself in `wallpaper.cpp` on a `_gles_interval_active` atomic (decided i/Q4.2** — gate the rotate fn, covering all callers, not just the POI wrap). The flag is set via a new **`nativeSetIntervalActive(boolean)` JNI (decided j/Q4.3)**, written from the `SETTINGS_CHANGED` receiver and the cold-start read: **true for indices 1–4, false for index 0**. **Threading (corrected during plan-writing):** `_gles_interval_active` is a *persistent level gate*, not a one-shot action — the JNI setter writes the `std::atomic<bool>` **directly** (mirroring `nativePrepareBackground`'s `_gles_jump_waypoint = true`, `sdl2_gles_v.cpp:105`); it is **read**, not exchange-drained, inside `RequestNextTitleMap()`, which already executes under `game_state_mutex` because `PrepareBackground()` is invoked from the mutex-guarded drain (`sdl2_gles_v.cpp:467-471`). (Only `_gles_refresh_title_maps` — a one-shot action — uses the exchange-drain.) This makes the interval Handler (1–4) or the natural POI-wrap cadence (0) the single title-map-rotation authority — no double-fire. `gles_poi.cpp` needs no edit (the gate lives in its callee).

### 3. Map zoom — DROP (decided, was open decision a)

- The zoom pref (`KEY_MAP_ZOOM`, `ZOOM_VALUES={1,2,4}`, `zoom_*` strings) has no UI and no consumer, and its only ex-consumer `nativeCycleZoom` is **confirmed absent** in the landed Stage 1 (no Java decl, no JNI export, empty `onTouchEvent`). POI zoom is a per-POI native choice (`In4x`/`In2x`, cluster-driven) — carried in `GlesPOI.zoom` and materialized by the (now-landed) Stage-2 scanner.
- **Decided (a): drop the pref** — delete `KEY_MAP_ZOOM`/`DEFAULT_MAP_ZOOM`/`ZOOM_VALUES`/getters/setters/`zoom_*` strings/`map_zoom_title`, and the `zoom` extra in `notifySettingsChanged` + the `zoom` read in the service receiver. A global zoom override fights the POI scanner's own zoom-out decisions and there is no native control for it, so wiring it is net-new scope for little value. This also satisfies "no dead scaffolding." No `nativeSetZoom`, no CMake/native change.
- **Rejected alternative (keep):** would add a new `nativeSetZoom(int)` JNI (confirmed not present today) + a global zoom bias in the POI camera + a UI selector — genuine new native feature work depending on the Stage-2 scanner, not a rewire. Reopen only if a user-facing zoom knob is explicitly required.

### 4. MapsActivity — propagate import/delete to a running wallpaper + hardening

- **Import/delete file ops already work** (SAF `GetContent` picker → copy stream to `filesDir/title/<DISPLAY_NAME>`; `AlertDialog` confirm delete; `canDelete = mapFiles.size() > 1` guard). Keep them.
- **Live propagation (new, required by the verification gate):** add a `TITLE_MAPS_CHANGED` broadcast that `MapsActivity` sends after a successful import or delete (verified net-new: `MapsActivity.java` has no `sendBroadcast`/native call today — only `refreshList()`). The `:wallpaper` service registers a receiver **with `RECEIVER_EXPORTED` (decided Q3.2)** — matching every existing receiver in the service for consistency (the intent is app-internal, so exposure is low-risk) — that calls a **new native `nativeRefreshTitleMaps()`** → sets a new atomic (e.g. `_gles_refresh_title_maps`) drained in `ProcessOverlayActions` under `game_state_mutex`, which rebuilds `_title_files` via `BuildTitleFileList()` and clamps `_title_file_idx` to the new size. This is the only way a change made in the default-process `MapsActivity` reaches the native static cache in `:wallpaper` without a process restart. Add the matching JNI export in `sdl2_gles_v.cpp`. **Follow the device-validated drain, not the risky precedent:** route through the real `ProcessOverlayActions` atomic-drain (`sdl2_gles_v.cpp:454-489`, `game_state_mutex` at :467, the Stage-1 "Fix C" that closed the GL-thread window/viewport race), exactly like `nativeRotateMap` — NOT a direct `BuildTitleFileList()` call on the JNI thread the way `nativeSwitchMap` (:108-112) does (a known latent race). Keep the 1:1 Java-native↔JNI-export invariant (extend the Stage-1 assertion to 14/14).
- **Bundled-vs-imported delete wart:** `copyAssetsStatic` → `copyAssetDir` re-copies bundled maps every launch (verified: the file branch writes with no dest-existence check; the only `.exists()` checks are dir mkdirs), so deleting a bundled map does not persist. **Decided (d): copy-once** — make the title-file copy skip when the dest file already exists (or gate on an `assets_copied` marker pref) so deletes stick for everything. Rejected alternative: treat bundled maps as permanent defaults + hide delete on bundled names (needs bundled-vs-imported detection and confuses "delete" semantics). The "can't delete the last map" guard (`mapFiles.size() > 1`) stays; `opntitle.dat` (baseset, not in the `MapsActivity` `title/*.sav` list) is the rotation floor regardless.
- **Import validation (light hardening):** enforce/append `.sav` (the list filter already hides non-`.sav`, so a mis-picked file silently vanishes today); handle name collisions (overwrite is acceptable but should refresh + not duplicate). Deeper management (rename/reorder/preview) is out of scope — decision (c).

### 5. SETTINGS_CHANGED propagation & persistence (cross-process)

- `SettingsHelper.notifySettingsChanged` stays the single write+broadcast entry point (persist via `SharedPreferences.apply()`, then `sendBroadcast` with the extras). After the zoom decision it carries brightness + interval (+ zoom only if kept).
- The `:wallpaper` `SETTINGS_CHANGED` receiver applies **all** live-relevant settings (brightness push + interval re-arm), not just brightness. On process (re)start the service reads persisted values fresh (`SettingsHelper.getX`) **on the first `onVisibilityChanged(true)` (decided Q3.3)** — seed interval (arm the Handler) + brightness (push) there. Rationale: the first resume is guaranteed to run after native/GL is ready and a surface exists (unlike `onCreate`, where the brightness push would no-op and the Handler would arm before a surface), and brightness is already re-pushed on every `onVisibilityChanged(true)` (`OpenTTDWallpaperService.java:330`), so this reuses an existing hook. A wallpaper started cold thus honors saved prefs on its first show without needing a broadcast.
- Do **not** rely on cross-process in-memory `SharedPreferences` consistency (`MODE_MULTI_PROCESS` is deprecated/unreliable): the broadcast is the live signal; the persisted file is the source of truth read on start.

## Known risk

- **`nativeRefreshTitleMaps` touches game/loader state:** rebuilding `_title_files` is a filesystem scan (cheap, no map mutation) but it must run on the correct thread and not race an in-flight `LoadNextTitleMap`. **Mitigation (now grounded in real code):** route it through the existing GL-thread atomic drain in `ProcessOverlayActions` (`sdl2_gles_v.cpp:454-489`) under `game_state_mutex` (:467) — the same device-validated mechanism `nativeRotateMap` uses — rather than calling `BuildTitleFileList()` directly from the JNI thread (the `nativeSwitchMap` anti-pattern, a known latent race). Deleting the currently-loaded map is safe (Android/Linux keeps the open inode; next rotation skips the now-absent path).
- **Interval-driven rotation vs live POI-wrap rotation double-fire — REAL NOW (Stage 2 landed), RESOLVED:** the scored scanner's POI-wrap→`RequestNextTitleMap()` (`gles_poi.cpp:549-553`) is **live**. **Resolution:** gate `RequestNextTitleMap()` in `wallpaper.cpp` on a `_gles_interval_active` level flag (set directly via `nativeSetIntervalActive(boolean)`, read under `game_state_mutex` at the `PrepareBackground` drain site — not exchange-drained). For **index 0** the flag stays false — the POI-wrap rotate IS the cadence (index-0 reuses the existing on-hide `nativePrepareBackground`, no timer). For **indices 1–4** the flag is true — the Handler timer is the sole title-map-rotation authority and the wrap-rotate no-ops. `nativePrepareBackground`'s POI *camera* advance is unaffected either way. Stage-4 code task: `wallpaper.cpp` gate + `nativeSetIntervalActive` JNI in `sdl2_gles_v.cpp`; `gles_poi.cpp` unchanged.
- **Delete not persisting for bundled maps** (copyAssetsStatic overwrite) — addressed in scope §4; call out in verification so the tester deletes an *imported* map (or a bundled one after the copy-once fix).
